# TodoList Constitution

## Core Principles

### I. Clean Code

- Code MUST be clear, maintainable, and concise.
- Avoid unnecessary complexity; prioritize readability and simplicity.
- Code organization follows best practices for ease of future modifications.

### II. Simple UX

- The user experience MUST be intuitive and straightforward.
- Features should be accessible with minimal user friction.
- Avoid overloading interfaces; focus on essential user tasks.

### III. Responsive Design

- UI MUST adapt gracefully to all screen sizes, from mobile to desktop.
- Utilize responsive CSS and layout techniques to ensure usability.

### IV. No Testing Mandate

- The project explicitly WILL NOT require unit, integration, or end-to-end tests.
- No test gate or automated test requirements will be enforced.

### V. Technology Stack

- The project MUST use React for UI development.
- Tailwind CSS MUST be used for styling and layout.

## Additional Constraints

- Emphasis on a clean, performant frontend experience.
- No backend or API constraints specified.

## Development Workflow

- Development focuses on feature delivery without formal testing.
- Code reviews and manual validation are recommended but not enforced.

## Governance

- Amendments require documented approval and version increment.
- Versioning policy follows semantic versioning principles.
- Major changes: incompatible principle changes or removals.
- Minor changes: additions or material expansions of principles.
- Patch changes: clarifications or wording improvements.
